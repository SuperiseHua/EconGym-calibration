## 4. 尚未完成的适配与核对事项

### 4.1 继续在校准目录内完成的工作

1. **目标与时期接口：**把观测年份、模型期数、政策路径、初始值和拟合／留出划分组织成明确输入；对缺失或不可比指标返回缺失状态，不能静默补零或改用其他物价指标。
2. **验收接口：**把任务书的逐轴 MAE、逐 seed 分布、稳定性及失败轨迹完整性统一到一份报告；通用核心的 RMSE 搜索评分与任务书验收分开。
3. **微观测量接口：**在校准层处理 SCF 家庭／插补标识、权重、收入与资产定义；不直接复用上游特殊归一化 Gini 作为现实验收。
4. **全部门核算接口：**逐式列出所需期初／期末状态、流量和尺度 S；先尝试在外部 adapter 重建，不能只用银行闭合替代所有部门核算。
5. **交付与调用接口：**补齐统一任务配置、输出 schema、依赖说明及配置导出；只有满足约定验收后才能生成带 calibrated 命名的配置。

以上以配置／替身／单元测试先验收，完成接口对齐后再进入真实模拟器测试。当前真实目标入口仍关闭是因为这些接口与测量定义尚未完整，不是要求每一个开发测试都进行正式种子授权。

## 5. 后续执行顺序

1. **当前阶段：接齐剩余任务书接口。**真实数据缺口、测量歧义和确需上游暴露的字段单独列出，不用优化器绕过。
2. **接口齐备后：做软件运行测试。**先小规模单路径，再前后端一致性、重复性、三参数传递、失败记录与校准闭环；目标是排除接口问题，不评判预测强弱。

本阶段不以改善预测为验收门，不加入新经济机制，不重跑旧正式实验。

## 6. 仅执行接口检查的方法

在仓库根目录、安装协作者所需配置依赖的环境中：

```powershell
python -B calibration/check_interfaces.py --repo . --output calibration/runs/new_interface_check
python -B calibration/launch.py --repo . prepare --data-bundle calibration/data/collected_v1 --n 1000 --horizon 27 --output calibration/runs/new_prepare
```

第一个命令执行单元／配置／数据检查，其中独立进程由替身代替；第二个命令只生成配置和数据就绪摘要。输出目录必须是新目录。

**本阶段不要运行 `audit.py`**：该旧检查脚本包含真实仿真及参数响应实验。也不运行 `evaluate`、`synthetic-calibrate` 或任何正式校准／验收组。
